# Pete Media Fotography — Website Launch Kit

This is a ready-to-upload static website starter. It is intentionally supplied with clearly named image/video placeholders. It does NOT contain invented client work, fake testimonials, unapproved prices, or a pretend AI receptionist.

## 1. Prepare your real assets first

Use only photographs and films Pete Media owns or has permission to publish. Get client permission for identifiable people, especially children. Do not upload private client galleries, identity documents, phone lists, contracts, or unwatermarked full-resolution originals.

### Brand
- `assets/brand/logo.png` — transparent PNG logo, ideally 1000 px wide or larger.
- `assets/brand/favicon.png` — square logo icon.
- Replace the PM text monogram in `index.html` if you want your actual logo displayed in the header.

### Photos
Export web-ready JPEGs (sRGB, ideally 1600–2200 px long edge, quality around 78–85; keep each file reasonably small).
- `assets/photos/hero.jpg` — strongest signature image.
- `portfolio-01.jpg` — wedding.
- `portfolio-02.jpg` — portrait.
- `portfolio-03.jpg` — family.
- `portfolio-04.jpg` — traditional marriage.
- `portfolio-05.jpg` — event/corporate.
- `video-poster.jpg` — still image for the video player.

Keep the filenames exactly as above, or update the matching paths in `index.html`.

### Video
- `assets/videos/showreel.mp4` — a short 30–90 second showreel, MP4/H.264, 1080p.
For long wedding films, do not upload large files into the website repository. Use a video host with suitable privacy/embedding settings and replace the video element with its embed link. Do not publish client films without permission.

## 2. Upload to the existing GitHub website repository

1. On a computer, open GitHub and sign in to the account that owns `Petemedia/pete-media`.
2. Open the repository and check that you have **Write** or **Admin** access. If you cannot upload or commit files, ask the repository owner to grant the required permission. Do not share your password or access token.
3. Download and extract this ZIP on your computer.
4. Open the extracted `pete_media_launch_kit` folder. Select all its contents (`index.html`, `style.css`, `assets`, and this README) — upload the contents, not an extra nested folder.
5. In the repository, choose **Add file → Upload files**, drag the selected contents into the page, then commit the changes to the publishing branch (often `main`). If GitHub rejects the upload, stop and resolve repository permission rather than repeatedly trying.
6. In repository **Settings → Pages**, check the publishing source. For a simple setup, select the main branch and `/ (root)` if that matches the repository structure. Save.
7. Wait for the Pages deployment to finish in the **Actions** tab. Open the published site on both phone and computer and test every link. GitHub Pages can take several minutes to publish.

Official guide: https://docs.github.com/en/pages/quickstart

## 3. Content approval checklist — do not announce the portfolio as complete until these are done

- [ ] Owner-approved logo and favicon installed.
- [ ] At least 12–20 strong, permission-cleared photographs across 4–5 categories.
- [ ] At least one short approved showreel, or remove the video player until ready.
- [ ] Accurate business description, address, appointment-only note, phone numbers and social links.
- [ ] Owner-approved current price list. If prices vary, use “Request a quotation” instead of publishing unapproved numbers.
- [ ] Booking/payment policy reviewed and approved.
- [ ] No placeholder image boxes, broken links, stock photos, invented awards, or fake reviews remain.
- [ ] WhatsApp enquiry works on a phone.
- [ ] Mobile layout, load speed, spelling and contact details checked.
- [ ] Client permissions checked for all published work.

## 4. Important: what this starter does and does not do

It provides a responsive public-facing portfolio and direct WhatsApp enquiry route. It is not a booking database, payment system, client gallery, cloud archive, or live AI agent.

A genuine 24/7 AI receptionist needs a secure server-side backend, an AI service connection, usage limits, a privacy notice, and monitored escalation to a human. Never put private API keys in `index.html`, JavaScript, or a public GitHub repository. Start with the WhatsApp enquiry desk and a well-maintained FAQ; add AI only after the secure backend is ready.

## 5. Free visibility and advertising foundation

1. Claim or create an eligible Google Business Profile at https://business.google.com/add. Use the exact real business name, phone, website, categories and service area. If customers do not visit the studio during stated hours, configure it accurately as a service-area business and hide the address where appropriate. Verification is required for full management.
2. Complete the Instagram and Facebook business profiles with matching brand name, logo, bio, phone, website and location.
3. Publish a weekly set of real work: one portfolio carousel, one short behind-the-scenes clip, and one client-approved result/story. Add descriptive captions and location tags; do not use misleading claims.
4. Ask satisfied clients for honest reviews and reply professionally. Never buy reviews or offer rewards for positive reviews.
5. Use WhatsApp Business labels and quick replies to organise new enquiries, quotation sent, awaiting payment, confirmed, editing and delivered.
6. Track enquiries, confirmed bookings and where each client discovered you. This shows which free channels are working.

Free listings and organic posts are not guaranteed paid advertising or guaranteed rankings. Paid reach requires an advertising budget.
